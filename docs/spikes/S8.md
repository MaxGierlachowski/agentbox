# S8 – `agentbox connect` in the Bun binary

Date: 2026-11-22. Result: **pass, no Node helper needed.**

## Question
Can the Bun single binary use iroh-fetch 0.6.4's native engine (direct UDP paths) with a fixed
client key, including WebSockets, or must `agentbox connect` shell out to Node?

## Setup
macOS arm64 host, `iroh-gateway` v0.6.4 (darwin build, sha256 verified) in front of a Bun backend
that echoes `X-Iroh-Remote-Id` and runs a WebSocket echo; n0 public relays.

## Results
| Check | Bun 1.4.2 (source) | Node 24 | Bun `--compile` (stock) | Bun `--compile` + plugin |
|---|---|---|---|---|
| `createIrohFetch({engine:"native"})` | ✔ | ✔ | ✖ addon not found | ✔ |
| GET through gateway, `X-Iroh-Remote-Id` at backend | ✔ | ✔ | – | ✔ |
| WebSocket echo (`iroh.websocket`) | ✔ | ✔ | – | ✔ |
| Fixed identity via `secretKey` (same remote id) | ✔ | ✔ | – | ✔ |
| Path | direct (LAN, 0.2 ms) | direct | – | direct |

- Stock `bun build --compile` fails: iroh-fetch loads its prebuild with a dynamic
  `require("iroh-fetch-<tag>")`, and the WASM fallback reads `web_client_bg.wasm` from disk.
- Fix: `apps/agentbox/scripts/compile.ts` uses `Bun.build({ compile })` with a plugin that rewrites
  that one `require(id)` in `iroh-fetch/src/native.js` to a static require of the **target's**
  prebuilt addon (downloaded with `npm pack iroh-fetch-<tag>@0.6.4`). Bun embeds the `.node` file.
  The build fails loudly if the patched line changes in a future iroh-fetch.
- The gateway admin `/status` returns `endpoint_id`, so the config server reads the endpoint id
  there (no stdout scraping).
