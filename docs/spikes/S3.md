# S3 — Node 24.22.3 + Paseo 0.17.3 + Claude Code 2.1.330 headless

Date: 2026-11-22. Environment: `abvm:arm64` (Ubuntu 24.04.5 + systemd) on Docker Desktop, arm64 Mac. The minimal image has no `python3`, `make`, `g++` or `xz`, which also proves that no build tools are needed.
x64 was not run (Docker amd64 emulation is broken on this Mac right now, `exec format error`). Desk check: `node-v24.22.3-linux-x64.tar.gz` is in SHASUMS256 (`061ec3e3…acc2`), and `@anthropic-ai/claude-code-linux-x64@2.1.330`, `@anthropic-ai/claude-agent-sdk-linux-x64@0.3.326`, `sherpa-onnx-linux-x64@1.12.28`, `@esbuild/linux-x64@0.25.12` and node-pty `prebuilds/linux-x64` all exist. Run the scripts once on a GitHub `ubuntu-24.04` runner.

Deliverables: `install-node.sh`, `install-paseo.sh`, `install-claude.sh` (all run fresh, then re-run for idempotency), `agentbox-paseo.service`, `agentbox.target`, `S3-help.txt` (paseo help dump).

## Node (`install-node.sh`)
- Downloads `https://nodejs.org/dist/v24.22.3/node-v24.22.3-linux-{arm64,x64}.tar.gz` (gz, so `xz-utils` isn't needed) and `SHASUMS256.txt`, and verifies with `sha256sum -c`. `NODE_SHASUMS_SHA256` / `NODE_TARBALL_SHA256` can pin the hashes in the manifest so trust doesn't rest on HTTPS alone. arm64 tarball sha256 `261af2af250dfd7e9f25cf151d1b2713a0adf8f10a9ad116c4947f68627affe8`.
- Extracted root-owned into `/opt/agentbox/vendor/node/24.22.3`. Wrappers `/usr/local/bin/{node,npm,npx}` are small sh scripts that exec the pinned binary and prepend its `bin/` to PATH, so npm's lifecycle scripts find the same node.
- Global npmrc `$tree/etc/npmrc` sets `update-notifier=false`, `fund=false`, `audit=false`. Caveat: with `--prefix X`, npm reads `X/etc/npmrc` instead, so the install scripts also pass `npm_config_update_notifier=false`. Without it, `npm notice New major version of npm available! 11.19.1 -> 12.2.3` shows up.
- The official Node 24 runs on minimal noble without `libatomic1`. Hermes' Node 26 does not; see S2.

## Paseo (`install-paseo.sh`)
- `npm install -g --prefix /opt/agentbox/vendor/paseo/0.17.3.staging @getpaseo/cli@0.17.3`, then an atomic rename; root-owned. Wrapper `/usr/local/bin/paseo` sets a default `PASEO_HOME`.
- **No build tools needed.** All native pieces are prebuilt: node-pty `1.2.0-beta.15` (`prebuilds/linux-{x64,arm64}/pty.node`), `sherpa-onnx-node` → `sherpa-onnx-linux-<arch>`, `@esbuild/linux-<arch>`, `@msgpackr-extract/*`. Install scripts must run (no `--ignore-scripts`).
- **Size:** 707 MB, of which **354 MB is `@anthropic-ai/claude-agent-sdk-linux-<arch>`**: a bundled Claude Code **2.1.326** binary from the agent SDK (0.3.326). Paseo does *not* use it for agents. `resolveClaudeBinary()` resolves `claude` from PATH (or the provider `command` setting) and passes it as `pathToClaudeCodeExecutable`, so agents run `/usr/local/bin/claude` = 2.1.330. Deleting that package would save 354 MB, but that is untested.
- Config is set with the CLI instead of hand-editing (local operation, no daemon needed; schema-validated; unknown path exits 1 with `Error: Unknown configuration path: no.such…`; a running daemon hot-reloads `config.json`):
  ```sh
  paseo daemon config set daemon.listen 127.0.0.1:6767 --home ~/.paseo
  paseo daemon config set daemon.relay.enabled false
  paseo daemon config set daemon.mcp.injectIntoAgents true
  paseo daemon config set daemon.browserTools.enabled false
  paseo daemon config set daemon.cors.allowedOrigins '[]'      # default ["https://app.paseo.sh"]
  paseo daemon config set features.webUi.enabled false
  paseo daemon config set features.dictation.enabled false    # !! see below
  paseo daemon config set features.voiceMode.enabled false
  ```
  JSON output of `config set`: `{"action":"saved","applied":false,"message":"Saved; not applied to a running daemon",…}` (exit 0). `config get <path> --json` returns `{"source":"configured","path":…,"value":…}`. The resulting `config.json` (0600) also gets `version: 1` and `app.baseUrl: https://app.paseo.sh` (materialized defaults).
- **Dictation is on by default.** At daemon start Paseo began a background download from GitHub of the local STT model `parakeet-tdt-0.6b-v2-int8`: **461 MB** into `~/.paseo/models/local-speech`. On minimal Ubuntu the extraction then failed (`tar (child): lbzip2: Cannot exec`). With `features.dictation.enabled false` nothing is downloaded.

### `agentbox-paseo.service`
`ExecStart=/usr/local/bin/paseo daemon run --home /home/agentbox/.paseo`, `User=agentbox`, `PASEO_HOME`, belt-and-braces env `PASEO_LISTEN=127.0.0.1:6767 PASEO_RELAY_ENABLED=false PASEO_WEB_UI_ENABLED=false`, `PATH=/usr/local/bin:/usr/bin:/bin`, `DISABLE_AUTOUPDATER=1` (inherited by agents), `ExecReload=paseo daemon reload`, `Restart=always`, `KillMode=process`, `TimeoutStopSec=30`.

Verified:
- `curl 127.0.0.1:6767/api/health` returns `{"status":"ok","timestamp":"…"}` about 2 s after start.
- `ss -tlnp`: `127.0.0.1:6767` plus a second **`127.0.0.1:<random>`** (answers 401; the local IPC/credentialed endpoint, plugins connect as `peer:"local_ipc"`). **No IPv6 listeners, no wildcard.**
- **No relay/outbound connections:** with dictation off, `ss -tunpa` sampled every second for 40 s (and again for 30 s on the fresh box) showed no non-loopback connection from the daemon. The daemon log has no "relay" lines. `paseo daemon status` reports `relay: {"enabled":false,"endpoint":"relay.paseo.sh:443",…}`. The only outbound connection seen at all was the dictation model download to GitHub (185.199.109.133:443), before it was turned off.
- Process tree: `paseo daemon run` (node), then "Paseo Supervisor", then "Paseo Daemon" (worker), plus `terminal-worker.mjs`, which Paseo copies into `~/.paseo/terminal-worker/0.17.3-<hash>/`. `systemctl stop` takes <0.1 s and the whole tree exits (nothing lingers despite `KillMode=process`). Agent survival across restarts was **not** tested (no agents logged in).
- Idle memory about 455 MB (13 built-in plugins load: usage sources, worktree-include, …). Paseo writes to `~/.paseo`: `config.json`, `daemon-keypair.json`, `local-credential`, `server-id`, `daemon.log`, `paseo.pid`, `runtime/`, `schedules/`, `terminal-worker/`.
- `paseo daemon status`: `listen 127.0.0.1:6767`, `daemonNode /opt/agentbox/vendor/node/24.22.3/bin/node`, `providers: claude available:true`. The others (codex, copilot, opencode, pi, antigravity, muse) are unavailable; muse shows `error`. Consider `agents.providers.<id>.enabled=false` for unused built-ins to stop the probing.

## Claude Code (`install-claude.sh`)
- `npm install -g --prefix /opt/agentbox/vendor/agent-clis @anthropic-ai/claude-code@2.1.330` adds 2 packages. The wrapper package's `postinstall` (`node install.cjs`) hard-links the native binary from `@anthropic-ai/claude-code-linux-<arch>` (optional dep) to `bin/claude.exe` (380 MB ELF). So **scripts must run**.
- Wrapper `/usr/local/bin/claude`:
  ```sh
  export DISABLE_AUTOUPDATER=1
  export DISABLE_UPDATES=1            # `claude update` → "Updates are disabled by your administrator…" (exit 0)
  export DISABLE_INSTALLATION_CHECKS=1
  exec /opt/agentbox/vendor/agent-clis/bin/claude "$@"
  ```
  Without these, a root `claude update` ran a network check and wrote `installMethod: global` into `~/.claude.json`.
- `claude --version` prints `2.1.330 (Claude Code)` (exit 0). On first run it creates `.claude.json`, `.claude.json.lock/` and `backups/` in `CLAUDE_CONFIG_DIR`.
- `CLAUDE_CONFIG_DIR=/home/agentbox/.claude-accounts/<slug> claude auth status` when logged out, **exit 1**, JSON by default:
  ```json
  {"loggedIn": false, "authMethod": "none", "apiProvider": "firstParty", "analyticsDisabled": false,
   "projectsDirectory": "/home/agentbox/.claude-accounts/spike/projects",
   "configDirectory": "/home/agentbox/.claude-accounts/spike", "loginExpiresAt": null,
   "consoleProfileSignInOffered": true}
  ```
  `--text` prints `Not logged in. Run claude auth login to authenticate.` (exit 1). `--json` is the explicit default.

## Surprises vs the plan
1. Paseo turns on **local dictation by default** and downloads a 461 MB model from GitHub at first start (it also needs `bzip2`/`lbzip2` to unpack). It must be disabled for the "no outbound" posture and for disk.
2. Paseo's npm prefix is 707 MB because it **bundles its own Claude binary (2.1.326)** through the agent SDK. Agents still use PATH `claude` (2.1.330), so the plan's pin holds, but the disk estimate must grow.
3. `daemon.cors.allowedOrigins` defaults to `https://app.paseo.sh`. The plan doesn't mention it; set it to `[]` (nothing external needs browser access to :6767).
4. A second loopback listener on a random port (credentialed IPC). `ss` checks must allow it, and must not assume 6767 is the only port.
5. `paseo daemon config set` works offline and validates input. Use it instead of jq/YAML edits (§12.2 already names it).
6. `npm notice` update banners unless `npm_config_update_notifier=false`. `claude` needs `DISABLE_UPDATES=1` + `DISABLE_INSTALLATION_CHECKS=1` on top of `DISABLE_AUTOUPDATER=1`.
7. No native build toolchain is needed for Paseo or Claude on noble (arm64 verified). The plan's `build-essential` apt entry is not needed for these components.

- §12.2 config list: add `daemon.cors.allowedOrigins []`, `features.dictation.enabled false`, `features.voiceMode.enabled false`, optionally disable unused built-in providers. Keep the env equivalents in the unit.
- §5.3 Paseo unit: `ExecStart=paseo daemon run --home …` verified; add `ExecReload=paseo daemon reload`, `PATH=/usr/local/bin:/usr/bin:/bin`, `DISABLE_AUTOUPDATER=1`.
- §4 Claude row: wrapper env `DISABLE_AUTOUPDATER=1 DISABLE_UPDATES=1 DISABLE_INSTALLATION_CHECKS=1`; postinstall must run.
- §16 e2e: `ss` assertion = every agentbox-owned listener on 127.0.0.1 (Paseo and Hermes each add one random loopback port), no `0.0.0.0`/`[::]` apart from sshd and LAN-mode :8443.
- §4 Node row: use `.tar.gz`; pin the SHASUMS256 hash in the manifest; wrappers are scripts, not symlinks.
