## Questions and answers

| # | Question | Result |
|---|---|---|
| a | Is the calling session's key available inside the tool-call path (`pre_tool_call`)? | **Yes.** The hook ran for `mcp__paseo__paseo_create_agent` called through Hermes' deferred `tool_call` bridge and read `HERMES_SESSION_KEY = agent:main:local:dm:<session_id>` from the task-local session context. Hermes runs hook callbacks in `contextvars.copy_context()` of the tool call (`plugins_dispatch._run_hook_callback_bounded`). The labels arrived at the MCP server; the model's own label (`todo: T-1`) was kept. |
| b | Does `ctx.inject_message(content, role="user", session_key=…)` reach and resume a Hermes-UI-originated (`local`) session? | **Yes.** A session created like hermes-ui does (gateway WS `session.create {source: "gui"}` + `prompt.submit`) received the injected notice as a new turn of **the same session** (history grew 4 → 6 → … → 14 messages over the run, first user message unchanged), 2.06 s after the webhook with `coalesce_seconds: 2`. The WS client got the `message.start`/`message.complete` events of the injected turn. |
| b2 | …with no client attached? | **Yes.** Same result after the WS client disconnected. |
| b3 | …after a gateway restart (no client)? | **Yes.** An event stored `pending` when the gateway was stopped (SIGTERM inside the coalescing window) was restored and injected after `hermes gateway run` came back; the gateway resumed the session from disk (its history kept growing, 12 → 14). |
| c | Receiver binds 127.0.0.1 only and only when the gateway runs? | **Yes.** No listener before `hermes gateway run` (also not during `hermes plugins list`); `ss -ltnp` shows `127.0.0.1:8645` owned by the gateway process; closed on stop. |
| d | Event loss across a Hermes restart? | **None** for both intakes: webhook (event on disk before 202, restored on start) and long-poll (event emitted while the gateway was **down** — stop 18:28:50.9, emit 18:28:51, bridge back 18:28:58 — injected at 18:29:00 from the persisted cursor). |

**Decision:** in-process plugin as planned. The sidecar fallback (gateway WS `session.resume` + `prompt.submit`) is not needed and was not built.

## Findings that change the plan

1. **Use `gateway.session_context.get_session_env("HERMES_SESSION_KEY")`, not `bound_session_key()`.**
   `hermes plugins doctor` flags `bound_session_key` as a *private core import* (catalog rule 9);
   `get_session_env` is on Hermes' public plugin API list (`website/docs/developer-guide/plugins/public-api.md`)
   and reads the same ContextVar. Plan §12.3 should say `get_session_env`.
2. **MCP tool names are `mcp__<server>__<tool>`** (double underscore, `tools/mcp_tool_schema.py`), e.g.
   `mcp__paseo__paseo_create_agent`. By default they are **deferred**: the model sees `tool_search` /
   `tool_describe` / `tool_call {calls:[{name, arguments}]}`; Hermes unwraps `tool_call` before
   `pre_tool_call`, so the hook still sees the real tool name. Match globs `mcp__*__paseo_create_agent`.
3. **`paseo_send_message` has no `labels`** (paseo-mcp's zod schema drops unknown keys), so steering
   cannot re-tag an agent. The bridge records `agent_id → session key` on that call and routes the
   agent's next events there (prefix ids supported, as paseo-mcp accepts them).
4. **paseo-mcp webhooks pause after 5 failed deliveries in a row and then drop events** until resumed.
   For "no loss while Hermes is down" the bridge now also has a **long-poll intake** (`paseo_wait_for_events`
   over paseo-mcp's HTTP endpoint with a `read` token, cursor in the plugin's SQLite store). It does not
   use `ctx.call_mcp` (needs `mcp_allowlist`, and would hold Hermes' MCP client for minutes) and uses
   threads instead of `ctx.spawn_task` (no running loop at `register()` time).
5. **`allow_gateway_injection: true` is required** under `plugins.entries.hermes-paseo-bridge` (Hermes
   permission, default off). `mcp_allowlist` is not needed.
6. Gateway-local session keys look like `agent:main:local:dm:local-<hex>`; the `hermes_profile` label is
   `ctx.profile_name` (`default`). hermes-ui sessions show `platform=desktop` in Hermes logs.
7. The gateway answers the WS upgrade with **HTTP 403 for a few seconds after start**, even though the
   control socket already hands out tickets. Clients (hermes-ui) should retry the connect.
8. S2-relevant: a bare `ubuntu:24.04` needs **`libatomic1`** before `setup-hermes.sh --runtime-only`
   (the pinned node fails verification without it); `cua-driver` (optional) fails without `libXi.so.6`
   and is skipped. Install took ~20 s after the first run. The runtime Python is CPython 3.14.9 in
   `$HERMES_HOME/tools/`, the venv under `$HERMES_HOME/installs/<id>/environments/<id>/venv`; the
   launcher is `<checkout>/hermes`, run through `scripts/run-in-hermes-env`. `hermes gateway run`
   exits 1 on SIGTERM ("so the service manager can revive the gateway").

## What agentbox renders (for WP-AB-7)

`$HERMES_HOME/config.yaml`:

```yaml
plugins:
  enabled: [hermes-paseo-bridge]          # or: hermes plugins enable hermes-paseo-bridge
  entries:
    hermes-paseo-bridge:
      allow_gateway_injection: true
      settings:
        listen_port: 8645                 # loopback receiver (127.0.0.1 is the default and enforced)
        paseo_mcp_url: http://127.0.0.1:6790/mcp   # long-poll intake (recommended on the box)
        fallback: {mode: home}            # no session -> home channel summary, else log
```

`$HERMES_HOME/.env` (or the rendered unit env): `HERMES_PASEO_BRIDGE_SECRET=<32+ random chars>` (webhook
intake) and/or `HERMES_PASEO_BRIDGE_PASEO_MCP_TOKEN=<paseo-mcp read token>` (long-poll). Every setting also
has an env override `HERMES_PASEO_BRIDGE_<KEY>` (README of the repo lists them).

paseo-mcp side: either a webhook `http://127.0.0.1:8645/paseo/events`, signature `standard-webhooks`, the
same secret, types `agent.turn_ended, agent.permission_requested, agent.closed`, label filter
`origin=hermes`, batching off — or just a `read` token for the long-poll (events enabled). Add port
**8645** (bridge receiver, loopback) to the ports table in `v1-interfaces.md`.
