## Flow shapes

### Claude: `CLAUDE_CONFIG_DIR=… claude auth login --claudeai`
```
Opening browser to sign in…
If the browser didn't open, visit:
ESC]8;;https://claude.ai/oauth/authorize?<opaque 43-45 chars>BEL ESC[94mhttps://claude.ai/oauth/authorize?<same>ESC[39m ESC]8;;BEL
Paste code here if prompted > ESC[?25h
```
- The URL is a **short opaque link** (`authorize?z-…`), no longer the long query-string URL. It is printed twice: as an OSC 8 hyperlink target and as visible text.
- In parallel it **listens on `127.0.0.1:<random>`** for the browser redirect (seen with `ss`). The user's browser is elsewhere, so the box uses paste-code.
- Paste format: the callback page shows `code#state`. Write `<code#state>\r` to the PTY. On a bad code: `Signing in…`, then `Couldn't log in: That code wasn't accepted. It may be incomplete, expired, already used, or from an earlier sign-in attempt. Sign in again to get a new code.`, **exit 1**.
- No terminal queries are sent. SIGINT exits 0.
- Success strings (from the 2.1.330 binary, not captured): `Login successful.` and `Logged in as <email>`. Always confirm with `claude auth status` (below).

### gh: `gh auth login --web --git-protocol ssh --skip-ssh-key -s admin:public_key -h github.com`
```
ESC]11;?ESC\ ESC[6n                                  ← terminal queries (bg colour, cursor position)
! Did you know that expiring tokens can be requested with --expiring? …
! Failed to copy one-time code to clipboard
  No clipboard utilities available. Please install xsel, xclip, wl-clipboard …
! First copy your one-time code: ESC[0;1;39mXXXX-XXXXESC[0m
Press Enter to open https://github.com/login/device in your browser...
                                                    ← after Enter:
! Failed opening a web browser at https://github.com/login/device
  exec: "xdg-open,x-www-browser,www-browser,wslview": executable file not found in $PATH
  Please try entering the URL in your browser manually
                                                    ← then polls silently until authorized
```
- **5 s stall:** gh waits ~5 s for answers to `ESC]11;?` and `ESC[6n` before printing anything (timed: first output at 5.02 s). Answering `ESC]11;rgb:0000/0000/0000ESC\` and `ESC[1;1R` brings first output to 0.04 s. The PTY runner should answer DSR/OSC 11/DA1.
- Enter is needed to get past the prompt. The browser failure is harmless; polling continues. Send Enter right after the code is parsed.
- Code format `[A-Z0-9]{4}-[A-Z0-9]{4}` (hex-looking). SIGINT exit 0.
- Success strings (from the binary): `✓ Authentication complete.`, `- gh config set -h github.com git_protocol ssh`, `✓ Configured git protocol`, `✓ Logged in as <login>`.

### glab: `glab auth login --device …`
With the plan's flags **only** (`--device --hostname gitlab.com --git-protocol ssh`), glab 1.131 first shows a **huh/bubbletea form**: `┃ What domains does this host use for the container registry and image dependency proxy?` / `> gitlab.com,gitlab.com:443,registry.gitlab.com` (prefilled). It also enables bracketed paste, focus events and the kitty keyboard protocol, and prints `WARNING: The operating system keyring is unavailable. Storing credentials as plaintext in the configuration file.` Add `--container-registry-domains … --insecure-storage` and the flow is plain text:
```
ESC]11;?ESC\ESC[6n ESC]11;?ESC\ESC[6n
- Signing into gitlab.com

First copy your one-time code: XXXXXXXX
Then open this URL on any device to authorize: https://gitlab.com/oauth/device

Waiting for authorization...
ESC]11;?BEL ESC[c                                     ← on exit
```
- Code format on gitlab.com: **8 alphanumerics, no dash** (e.g. `S252KV2A` → `XXXXXXXX`). No "Press Enter". No `verification_uri_complete` is printed.
- **glab ignores SIGINT while waiting.** The capture needed SIGKILL after 1.5 s, so the runner must escalate (SIGTERM → SIGKILL).
- Success strings (from the binary): `Logged in as %s`, `Logged in to %s as %s (%s)`.

## Parsers (apply to ANSI-stripped text; strip CSI, OSC incl. OSC 8, DCS/APC, and `\r`)
```js
ANSI   = /\x1b\[[0-?]*[ -\/]*[@-~]|\x1b\][^\x07\x1b]*(?:\x07|\x1b\\)|\x1b[PX^_][^\x1b]*\x1b\\|\x1b[@-Z\\-_]/g
// claude
url          = /If the browser didn't open, visit:\s*\n?(https:\/\/\S+)/
pastePrompt  = /Paste code here if prompted >\s*$/m          // then write "<code#state>\r"
signingIn    = /Signing in…/
error        = /Couldn't log in: (.+)/
success      = /Login successful\.|Logged in as (.+)/
// gh
code         = /one-time code:\s*([A-Z0-9]{4}-[A-Z0-9]{4})/
enterPrompt  = /Press Enter to open (https:\/\/\S+) in your browser\.\.\./   // capture = verification URL; then write "\r"
browserFailed= /Failed opening a web browser at (https:\/\/\S+)/             // ignore
success      = /Authentication complete\.|Logged in as (\S+)/
// glab
registryPrompt = /What domains does this host use for the container registry/ // must never appear (pass the flag)
code         = /one-time code:\s*([A-Z0-9-]{6,})/
url          = /open this URL on any device to authorize:\s*(https:\/\/\S+)/
waiting      = /Waiting for authorization\.\.\./
success      = /Logged in as (\S+)|Logged in to (\S+) as (\S+)/
// terminal queries to answer (raw stream, before stripping)
\x1b[6n → "\x1b[1;1R"     \x1b]11;?(BEL|ST) → "\x1b]11;rgb:0000/0000/0000\x1b\\"     \x1b[c → "\x1b[?62;22c"
```
Parse the raw stream incrementally (chunks split anywhere): keep a stripped rolling buffer and match on it. Never log the buffer unredacted; it holds one-time codes.

## Surprises vs the plan
1. Claude's login URL is now a short opaque `claude.ai/oauth/authorize?<token>` link wrapped in OSC 8. A parser that expects `client_id=…&state=…` breaks. Match the line after "If the browser didn't open, visit:" instead.
2. glab's plan command stops at an interactive **container-registry-domains** TUI question. Add `--container-registry-domains gitlab.com,gitlab.com:443,registry.gitlab.com` (and `--insecure-storage`, since there is no keyring on the box). For self-managed hosts, also pass `--api-host`/`--ssh-hostname` where they differ, or other form prompts appear.
3. gh and glab query the terminal (OSC 11, DSR, DA1). Without replies gh stalls about 5 s.
4. gh needs an explicit Enter after the code. glab needs none. Claude needs the pasted `code#state`.
5. glab ignores SIGINT while polling, so the runner needs a SIGKILL fallback.
6. gh `--json` status always exits 0 (inspect `state`). glab and claude exit 1 when logged out.
7. Claude opens a loopback callback port during login; harmless, it closes on exit.

## Recommended plan changes
- §8 screen 6 glab command: `glab auth login --device --hostname gitlab.com --git-protocol ssh --container-registry-domains gitlab.com,gitlab.com:443,registry.gitlab.com --insecure-storage`.
- PTY runner (`apps/agentbox/src/pty/`): answer DSR/OSC 11/DA1; set `TERM=xterm-256color`, 120×40; per-CLI parser above; send `\r` for gh after the code; SIGTERM, then SIGKILL after 2 s; redact codes in run logs; success = `claude auth status` exit 0 / `gh auth status --json hosts` with `state=="success"` / `glab auth status --output json` exit 0.
- C8 claude login parser: key on the "visit:" line, not URL params. Paste input `<code#state>\r`; detect `Couldn't log in:` to offer a retry.
- Keep `s9-parsers.mjs` + fixtures as the unit-test seed for the agentbox PTY parsers.
