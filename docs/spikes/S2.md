# S2 — Hermes v0.23.3 headless on Ubuntu 24.04

Date: 2026-11-22. Environment: Docker Desktop on an arm64 Mac, `abvm:arm64` (Ubuntu 24.04.5 + systemd), 18 vCPU, ~8 GB shared.
Upstream tag `v0.23.3` = commit `caafe5389ae585ef77387a962aee05b1bcf17029` (annotated tag, 2026-11-19).
x64 was **not** run: Docker's amd64 emulation on this Mac currently fails with `exec format error` for every amd64 image (also for other agents' containers), so only the x64 artifact pins were desk-checked (uv, CPython, Node, ffmpeg, ripgrep all have `linux-x64` entries in `pm/lock.json`). Run `install-hermes.sh` once on a GitHub Actions `ubuntu-24.04` runner before calling x64 done.

Deliverables: `install-hermes.sh` (tested end to end in a fresh container, then re-run for idempotency), `agentbox-hermes.service`, `agentbox.target`, `S2-help.txt` (help for 36 subcommands, all exit 0), fixture `fixtures/hermes-anthropic-oauth.txt`.

## Verdict
Hermes installs headless and the gateway runs under an agentbox-owned system unit with no model configured. **One premise of the plan is wrong:** the install can't be "root-owned, read-only `/opt/agentbox/vendor/hermes-agent/<tag>`" for everything. The code checkout can be. The pm-managed runtime (uv, CPython 3.14, Node 26, ffmpeg, the venv) lives in `HERMES_HOME/{tools,installs}` and **must be owned by the service user**. Most config verbs work non-interactively. `hermes mcp add` and `hermes skills install <local dir>` don't, and each has a working alternative (below).

## Install (what `install-hermes.sh` does)
```sh
sudo ./install-hermes.sh v0.23.3 agentbox /home/agentbox/.hermes
# env: HERMES_EXTRAS="slack edge-tts stt-whisper anthropic" (default), HERMES_COMMIT=<sha> (optional pin), HERMES_FORCE=1
```
1. apt: `git ca-certificates curl libatomic1`. That's all; no `build-essential`, no `python3*`, no `xz-utils`, no `ffmpeg`. `libatomic1` is required: pm's pinned **Node 26.12.1** fails verification without it, and pm then tries `sudo -n apt-get install libatomic1`, which fails for a non-root user.
2. User `agentbox` (uid 10001) if missing.
3. `git clone --depth 1 --branch v0.23.3 https://github.com/NousResearch/hermes-agent /opt/agentbox/vendor/hermes-agent/v0.23.3` (430 MB, `.git` 108 MB, about 7 s), `chown -R root`, `chmod go-w`.
4. `git config --system --add safe.directory /opt/agentbox/vendor/hermes-agent/v0.23.3`. **Required.** Hermes runs git in its install dir to derive its version. As `agentbox` on a root-owned repo, git refuses ("dubious ownership") and `hermes --version` prints `vunknown`.
5. Stage the uv pinned in `pm/lock.json` (0.13.5, sha256 from the lock) into `$HERMES_HOME/tools/uv-0.13.5-<target>/`, the same slot `setup-hermes.sh` uses.
6. Bootstrap CPython 3.14 with `uv python install --no-bin --no-registry 3.14` into a temp dir (`UV_PYTHON_INSTALL_DIR`), deleted afterwards. Without that it lands in `/root/.local/share/uv` (91 MB).
7. `cd $SRC && $boot_py -m pm.cli install --without chromium --without cua-driver`. This installs tools (CPython 3.14.9, Node 26.12.1, npm, pnpm, ffmpeg 9.0.1, ripgrep) plus the venv with `[all]`.
8. `$boot_py -m pm.cli install --extra slack --extra edge-tts --extra stt-whisper --extra anthropic`. **`--without` and `--extra` can't be combined** (pm: "--without shapes the default closure"), so it takes two calls. Extras are unioned with the recorded selection. Resulting `facts.json` extras: `all, anthropic, edge-tts, slack, stt-whisper, wecom`.
9. `chown -R agentbox: $HERMES_HOME`, write the wrapper, set the pin-holding config (below), write the stamp `$SRC/.agentbox-install.json`. A re-run with the same args skips pm.

The installer runs as root with `HERMES_HOME=/home/agentbox/.hermes`, so pm publishes its launchers into the root-owned checkout (`$SRC/.hermes/bin/{hermes,hermes-acp}`). Those launchers `exec /home/agentbox/.hermes/tools/python-3.14.9+…/bin/python3 -I -c …` with `sys.path` pinned to `$SRC`.

**Do not use `setup-hermes.sh --runtime-only`.** It is the dev entry point and always passes `--test-environment`, which also builds the isolated test environment and developer tools. The upstream user installer (`scripts/install.sh`) calls `python -m pm.cli install` directly, and the script above does the same.

### Wrapper `/usr/local/bin/hermes`
```sh
#!/bin/sh
export HERMES_HOME="${HERMES_HOME:-/home/agentbox/.hermes}"
exec /opt/agentbox/vendor/hermes-agent/v0.23.3/.hermes/bin/hermes "$@"
```
`hermes --version` as agentbox prints `Hermes Agent v0.23.3 (2026.9.24) · stable · local caafe5389ae5`, `Python: 3.14.9`, exit 0, 0.3 s. On first run Hermes also writes shims into `~agentbox/.local/bin/{hermes,hermes-acp,hermes-agent}` (inside the home dir, harmless).

### Where uv / Python / venv end up, and can they be root-owned?
- uv and CPython 3.14: `$HERMES_HOME/tools/` (override with `HERMES_RUNTIME_DIR`).
- venv: `$HERMES_HOME/installs/<sha256(checkout path)[:16]>/environments/<generation>/venv`, recorded in `installs/<key>/facts.json`.
- **They can't be root-owned or read-only.** Tested: after `chown -R root` of `tools/` and `installs/`, every `hermes` command fails with `hermes: install state is not writable by this user (…/installs/<key>/.recovery.lock)`. Making only the lock files writable leads to `pm-runtime/.prepare.lock`, then a "repairing the recorded dependency environment…" attempt, and the unit crash-loops (11 restarts). Hermes also extends the venv at runtime: `hermes plugins enable` printed "→ Installing Python dependencies…", and pm lazy-installs extras on first use.
- **The dependency state is per `HERMES_HOME`.** `HERMES_HOME=/tmp/h2 hermes chat` fails with `ModuleNotFoundError: No module named 'ruamel'`. Use profiles (`-p <name>`, which live under the same home), never a second `HERMES_HOME`.
- The only upstream read-only model is a *sealed payload* (Docker image: `pm.build_env --sealed --out /opt/hermes/.venv` plus `install-stamp.json` with `updateMechanism: external`; desktop: `hermes pm bundle --out`). It builds `--all-extras` plus Chromium and the like and is much heavier. Not worth it for v1.

### Auto-update, telemetry, plugin updates
| Concern | Default | Setting |
|---|---|---|
| Passive update check (`hermes --version` printed "Up to date", which is a network call) | on | `hermes config set updates.check false` → verified gone |
| `hermes update` | — | as agentbox it fails with exit 0: `Cannot lock this install for the update: …/.git/hermes-update.lock is not writable` (root-owned checkout). Pins hold by ownership. |
| Plugin update checks (gateway tick) | 24 h | `plugins.auto_update_check_hours 0` |
| Plugin auto-apply | false | `plugins.auto_apply false` (`hermes plugins auto-update off` prints the same state) |
| Shared-metrics telemetry | `enabled:false, send:false` | keep. The script leaves the defaults; `config get` already returns false. |
Also noticed: the `lsp` subsystem is on by default (`lsp.enabled`) and may fetch language servers on first use. Review that separately.

## systemd unit (`agentbox-hermes.service`)
`ExecStart=/usr/local/bin/hermes gateway run --replace --external-supervisor`, `User=agentbox`, `HERMES_HOME`, `EnvironmentFile=-/run/agentbox/env/hermes.env`, `Restart=always`, `KillMode=mixed`, **`TimeoutStopSec=90`**. Hermes checks its own unit: with 60 s it logs `Stale systemd unit detected: agentbox-hermes.service has TimeoutStopSec=60s but drain_timeout=0s cron_drain_timeout=30s (expected >=70s)`.

Results:
- It starts and stays up **with no model and no credentials**. Logs: banner, `Gateway control socket listening at /home/agentbox/.hermes/gateway.sock`, `No messaging platforms enabled.`, `Gateway will continue running for cron job execution.`, and 5 WARNING lines `Auxiliary Nous client unavailable … (code: nous_auth_missing)`. Those come from the default auxiliary provider `nous`; they are noise, but worth setting `auxiliary.*.provider` to `main` once a model exists. No errors.
- `/home/agentbox/.hermes/gateway.sock` (srw-------, agentbox) appears within about 2 s.
- `kill -9` gets restarted (NRestarts=1). `systemctl stop` takes 0.3 s and removes the socket.
- `gateway_state.json` holds `gateway_state: running`, `code_version`, `served_profiles`. A new `hermes profile create` is picked up live ("served now by the running multiplexed gateway").
- **Extra listener:** the gateway always binds an HTTP/WS API on `127.0.0.1:<random port>` (uvicorn: native session WebSocket `/api/ws`, plus the lazily mounted dashboard). `GET /api/health` returns `{"ok":true,"version":"0.23.3",…,"auth_required":false}`. It is loopback only, but any local uid can reach it.

### Webhook platform
`hermes config set platforms.webhook.enabled true` + `platforms.webhook.extra.host 127.0.0.1` (+ optional `extra.port 8644`), then restart:
- with host set: `LISTEN 127.0.0.1:8644` only; `curl 127.0.0.1:8644/health` returns `{"status": "ok", "platform": "webhook"}`
- **without host** (verified): `0.0.0.0:8644` **and** `[::]:8644`. The override is mandatory.
- Env equivalents: `WEBHOOK_ENABLED`, `WEBHOOK_PORT`, `WEBHOOK_SECRET`. There is no `WEBHOOK_HOST`, so the host has to go in config.yaml.

## Surprises vs the plan
1. **Venv and tools live in `HERMES_HOME`, ~1.8 GB, and must be agentbox-writable.** Only the code checkout is root/ro.
2. **`setup-hermes.sh --runtime-only` is the wrong entry point** (it builds the test env). Use `python -m pm.cli install` the way `scripts/install.sh` does.
3. pm brings its **own Node 26.12.1, ffmpeg 9.0.1, ripgrep, pnpm** into `HERMES_HOME/tools`. The plan's apt `ffmpeg` isn't needed for Hermes STT. Hermes' Node differs from the box's pinned Node 24.22.3.
4. `libatomic1` is a hard apt dependency (Node 26 on arm64).
5. Without `safe.directory`, Hermes reports `vunknown`.
6. Hermes ships **mcp SDK 2.x**: `mcp.server.fastmcp` raises "Removed in mcp 2: FastMCP is now `mcp.server.mcpserver.MCPServer`". Relevant for any Python MCP or plugin code (hermes-paseo-bridge).
7. `hermes mcp add` is an interactive wizard. Write `mcp_servers.<name>.*` with `hermes config set` instead.
8. `hermes skills install` has no local source. Use the `skills.external_dirs` setting.
9. Webhook default bind is `0.0.0.0` **and** `[::]` (confirmed).
10. The gateway owns a second loopback HTTP listener on a random port (unauthenticated `/api/health`).
11. `TimeoutStopSec` must be ≥ 70 s (Hermes warns otherwise).
12. `hermes --version` made an update check over the network until `updates.check false` was set.
13. `auth add` / `auth status` do no key validation. Validate keys in agentbox (cheap models call) or with `hermes chat -q ping` (exit 1 plus a "rejected your API key" message).

## Recommended plan changes
- §4 Hermes row: replace `setup-hermes.sh --runtime-only` with the `install-hermes.sh` steps (uv from `pm/lock.json` → `pm.cli install --without chromium --without cua-driver` → `pm.cli install --extra slack --extra edge-tts --extra stt-whisper --extra anthropic`). Location: checkout `/opt/agentbox/vendor/hermes-agent/<tag>` (root, ro) plus runtime in `HERMES_HOME/{tools,installs}` (agentbox). apt adds `git libatomic1`; drop `ffmpeg` unless something else needs it. Add `/etc/gitconfig safe.directory`.
- §5.2: document `HERMES_HOME/tools` and `installs` (~1.8 GB, regenerable). **Exclude them, plus `cache/` and `audio_cache/`, from `agentbox backup`.**
- §5.3 hermes unit: `TimeoutStopSec=90`. Health: `systemctl is-active` + `test -S $HERMES_HOME/gateway.sock` + `:8644/health` when the webhook is on (or `/api/health` on the random port from `gateway_state.json`/the rendezvous record).
- §12.1: render `updates.check: false`, `plugins.auto_update_check_hours: 0`, `plugins.auto_apply: false`, `platforms.webhook.extra.host: 127.0.0.1`. Set MCP servers with `hermes config set mcp_servers.<n>.{url|command|args|env|headers|enabled}` (stdio and HTTP; header values as `${ENV}` references to the rendered env file), **not** `hermes mcp add`.
- §9.4/§12.9: install agentbox skills via `skills.external_dirs` pointing at the release dir (read-only, versioned with agentbox) rather than copying into `~/.hermes/skills`.
- §8 screen 2: Hermes API key = `printf '%s\n' "$KEY" | hermes auth add <prov> --type api-key --label <l>` (stdin, no TTY, so no getpass prompt on `/dev/tty` because the server has no controlling terminal), then probe with `hermes chat -q ping -Q` (exit 1 on a bad key). Hermes OAuth for a Claude subscription is the same URL + paste-code PTY pattern as `claude auth login` (prompt `Authorization code: `).
- §8 screen 8: lowercase slugs yourself. Hermes lowercases silently instead of rejecting.
- hermes-paseo-bridge WP: target the mcp 2.x Python SDK.
