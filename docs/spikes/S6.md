# S6 — KasmVNC + Chrome + Caddy edge (2026-11-22)

Environment: Docker Desktop on an arm64 Mac, `abvm:arm64` (Ubuntu 24.04.5 + systemd, privileged).
Everything below ran under real systemd on **arm64**, twice: once while iterating and once from a
fresh container where the four install scripts ran in order (`--start`), then a second time to
prove idempotency, then the full test set. **x64 could not be executed** (see "x64" below); the
x64 artifacts were downloaded and hash-checked on the host.

Result: **pass, path prefix works.** `/browser/` behind Caddy (`handle_path` + websocket) serves
the KasmVNC client and Chrome is visible and usable in it (`S6-browser.png`, taken through
`http://127.0.0.1:8080/browser/` with forward_auth cookie). The 127.0.0.1:8082 fallback is not needed.

## 1. KasmVNC 1.5.2 — non-interactive first start: works

What the Perl wrapper (`/usr/bin/kasmvncserver`) needs so it never prompts, all pre-seeded by
`install-kasmvnc.sh` as user `agentbox` (uid 10001):

| Wrapper behaviour (read in the 1.5.2 source) | Pre-seed |
|---|---|
| Creates `~/.vnc/kasmvnc.yaml` if missing; with `command_line.prompt: true` (default) asks questions | own `~/.vnc/kasmvnc.yaml` with `command_line.prompt: false` |
| `EnsureAtLeastOneKasmUserExists`: with prompting off and **no user in `~/.kasmpasswd` it exits 1, even with `-DisableBasicAuth`** | `kasmvncpasswd -u agentbox -wo ~/.kasmpasswd` fed a random 24-char password on stdin (never printed/stored; basic auth is off anyway) |
| DE selection runs `select-de.sh` unless `~/.vnc/.de-was-selected` exists. **openbox is not in its list** (Cinnamon, Mate, LXDE, Lxqt, KDE, Gnome, XFCE, manual), so `-select-de openbox` from the plan fails | own `~/.vnc/xstartup` (`exec openbox-session`) + `touch ~/.vnc/.de-was-selected`; no `-select-de` flag |
| `StartXvncOrExit → CheckSslCertReadable` requires `pem_certificate`/`pem_key` to be readable **even with `require_ssl: false`**; the default snakeoil key needs `ssl-cert` group (and `ssl-cert` isn't even installed with `--no-install-recommends`) | private unused self-signed pair `~/.vnc/self.{pem,key}` (0600) referenced from the yaml |

`kasmvnc.yaml` (rendered): `network.protocol: http`, `interface: 127.0.0.1`, `websocket_port: 6901`,
`use_ipv6: false`, `udp.public_ip: 127.0.0.1`, `ssl.require_ssl: false` + the cert pair,
`desktop.allow_resize: true` (1600x900 initial), `user_session.session_type: shared`,
`concurrent_connections_prompt: false`, `idle_timeout: never`, `command_line.prompt: false`.

Unit (`agentbox-kasmvnc.service`, User=agentbox, Type=simple):
`ExecStart=/usr/bin/kasmvncserver :1 -fg -websocketPort 6901 -interface 127.0.0.1 -DisableBasicAuth`,
`ExecStartPre=/bin/rm -f /tmp/.X1-lock /tmp/.X11-unix/X1` (a SIGKILLed Xvnc leaves these and the
wrapper then refuses :1), `Restart=always`, `KillMode=control-group`, `Upholds=agentbox-chrome.service`.
With `-fg` the wrapper stays in the foreground for the lifetime of xstartup (openbox); when Xvnc
dies openbox exits, the wrapper exits and systemd restarts it.

Evidence:
- `curl 127.0.0.1:6901/` → 200, `<title>KasmVNC</title>` (70 KB index). Basic auth off.
- `ss -tlnp`: `127.0.0.1:6901 Xvnc` only. No IPv6 listener, no RFB 5901, X11 only on the unix socket.
- **But UDP: `0.0.0.0:6901 Xvnc`.** Xvnc's UDP transport always binds the wildcard on the websocket
  port; there is no interface option and `-udpPort` can't be disabled (`-udpPort -1` is rejected).
  Mitigation in `install-kasmvnc.sh` (belongs in `agentbox-firewall.service`):
  `iptables/ip6tables -A INPUT ! -i lo -p udp --dport 6901 -j DROP` — verified: packets from another
  container hit the DROP counter.
- `pkill -9 Xvnc` → unit back within ~5 s, Chrome back too (Upholds). `systemctl restart` fine.
- KasmVNC answers a websocket upgrade **without `Origin` with 404** and does **no Origin check** at all
  (an `Origin: http://evil.example` upgrade gets 101). Handled at the edge, see §3.

## 2. Browser — Google Chrome on both arches

**Finding: Google's apt repo now ships `google-chrome-stable` for arm64** (Release `Architectures:
amd64 arm64`, `google-chrome-stable 158.0.8127.36-1` in `binary-arm64`). So the plan's split
(x64 Chrome / arm64 Playwright Chromium) is unnecessary: one install path, real Chrome with Google
updates on both. Ran natively on arm64 under KasmVNC (`Chrome/158.0.8127.36`).

Repo handling: the current package postinst manages a **deb822** file
`/etc/apt/sources.list.d/google-chrome.sources` with URI `https://dl.google.com/linux/chrome-stable/deb/`
(new path, the old `/linux/chrome/deb/` still works) and `Signed-By: /usr/share/keyrings/google-chrome.gpg`,
re-creates it on every upgrade and deletes a legacy `google-chrome.list`. `install-browser.sh`
therefore fetches the key, checks the primary fingerprint, and writes exactly that file — so the
postinst rewrites identical content and apt never sees duplicate sources (verified with a purge +
reinstall and `apt-get update`).

Playwright 1.65.1's "chromium" for linux-arm64 is now just Google's **Chrome for Testing** build
(`cdn.playwright.dev/builds/cft/<v>/linux-arm64/…` redirects to `storage.googleapis.com/chrome-for-testing-public`).
The CfT fallback (`AGENTBOX_BROWSER_SOURCE=cft`, pinned zip + sha256, deps from its `deb.deps` with
noble `t64` renames, setuid `chrome-sandbox` installed next to the binary) works on arm64 and reuses
the same profile, but **shows a permanent "Chrome for Testing … is only for automated testing" infobar**
and gets no updates. Use only if the apt repo is unavailable.

Unit (`agentbox-chrome.service`, User=agentbox, `DISPLAY=:1`, `BindsTo=`+`After=agentbox-kasmvnc.service`):
flags exactly as planned (`--user-data-dir=/var/lib/agentbox/chrome-profile --remote-debugging-address=127.0.0.1
--remote-debugging-port=9333 --no-first-run --no-default-browser-check --disable-dev-shm-usage --start-maximized`)
plus `--password-store=basic`. Additions found necessary:

1. **Cookie loss on stop.** With the default `KillMode=control-group` + SIGTERM, cookies set within
   Chrome's ~30 s flush window were lost on `systemctl restart` (set → restart → gone; set → wait 40 s
   → restart → kept). `KillMode=mixed` alone did not fix it. Fix: `ExecStop=python3 chrome-cdp-close.py $MAINPID`
   (CDP `Browser.close`, then waits for the main PID), `KillMode=mixed`, `TimeoutStopSec=30`.
   After that the cookie survived 2× unit restart, a KasmVNC restart and an Xvnc SIGKILL.
   Production: `agentbox browser close --wait $MAINPID` instead of python.
2. **Chrome stays down after a display crash.** `BindsTo` stops Chrome when KasmVNC fails but nothing
   starts it again when KasmVNC auto-restarts → `Upholds=agentbox-chrome.service` in the KasmVNC unit.
3. `ExecStartPre` waits for `/tmp/.X11-unix/X1` (Xvnc is forked by the wrapper; avoids a start race).
   Consequence: neither unit may use `PrivateTmp=` (shared X socket).
4. `--password-store=basic`: no keyring in the openbox session; makes the (default) fallback explicit
   so Chrome never pops a keyring dialog and cookie encryption stays stable across restarts.
5. **No `--no-sandbox`.** `chrome://sandbox` reports "adequately sandboxed" (namespace sandbox +
   seccomp-BPF) in the container; the deb also installs the setuid `chrome-sandbox`. On a real
   Ubuntu 24.04 VM, unprivileged userns is AppArmor-restricted; Ubuntu ships a `chrome` AppArmor
   profile for `/opt/google/chrome/chrome` and the setuid helper is the fallback — **verify on the
   Proxmox VM** (CfT path relies on the setuid helper only).
6. Fonts: `fonts-noto-core fonts-noto-cjk fonts-noto-color-emoji` (CJK was tofu without `-cjk`).

Evidence: `curl 127.0.0.1:9333/json/version` → `"Browser": "Chrome/158.0.8127.36"`; listens
`127.0.0.1:9333` only. Cookie via CDP `Storage.setCookies` (persistent, 30 d) →
`systemctl restart agentbox-chrome` → `Storage.getCookies` still returns it (`cdp-cookie.py`).
Side note: Chrome also opens mDNS on 224.0.0.251:5353 (media router); harmless, could be turned off
with the `EnableMediaRouter=false` policy.

## 3. Caddy 2.11.9 edge (`agentbox-edge`)

Unit: `caddy run --config /etc/agentbox/Caddyfile --adapter caddyfile` as `agentbox-edge`,
`Type=notify`, `EnvironmentFile=/run/agentbox/env/caddy.env`, `ProtectSystem=strict`,
`ReadWritePaths=/var/lib/agentbox/caddy`, `ExecReload=caddy reload … --address unix//run/agentbox-caddy/admin.sock`.

Caddyfile decisions (see `Caddyfile`):
- **Admin API on a unix socket** in `RuntimeDirectory=agentbox-caddy` (0700, edge user) instead of
  TCP `localhost:2019`, which every local user — including agent code running as `agentbox` — could
  use to replace the config and drop auth. `systemctl reload` works through it.
- `storage file_system /var/lib/agentbox/caddy`, `skip_install_trust`, `auto_https disable_redirects`,
  `pki { ca local { name "agentbox local CA" } }`.
- `caddy validate` provisions the PKI (creates the CA) — run it **as the edge user**, otherwise the
  CA files end up root-owned and Caddy fails to start (hit this once).
- `:8443` needs host names for `tls internal`: site `https://@LAN_IP@:8443, https://localhost:8443,
  https://127.0.0.1:8443` + global `default_sni @LAN_IP@` (IP-literal clients send no SNI). Leaf cert
  SAN = `IP Address:<LAN_IP>`, issuer "agentbox local CA - ECC Intermediate". Caddy also opens
  UDP `*:8443` for HTTP/3 (add `servers { protocols h1 h2 }` if unwanted).
- `:8080` and `:8081` as `http://:PORT { bind 127.0.0.1 }` (any Host header matches).
- Every listener first deletes `X-Iroh-Remote-Id`, `X-Agentbox-User`, `X-Agentbox-Proxy-Secret`
  (`:8081` keeps `X-Iroh-Remote-Id`, which the gateway sets and spoof-strips), then
  `forward_auth 127.0.0.1:7777 { uri /api/auth/check; copy_headers X-Agentbox-User }`.
  Unauthenticated: `/healthz` (static), `/setup*`, `/api/auth/*`.
- `/hermes/*` → `handle_path` → 127.0.0.1:8787 with `request_header X-Agentbox-Proxy-Secret {env.AGENTBOX_PROXY_SECRET}`.
- **`/browser/` prefix:** `handle_path /browser/* { reverse_proxy 127.0.0.1:6901 }`. All client assets
  are relative (`./assets/…`), but the client builds its websocket URL as `"/" + setting("path")`
  with default `websockify`, i.e. `/websockify` at the origin root. Settings are read from the query
  string, so Caddy redirects `/browser/` (no `path=` query) once to `/browser/?path=browser/websockify`
  (302) and `/browser` → `/browser/` (308). No 4xx in the page's network log; WS handshake 101.
- **WS Origin check** (KasmVNC has none): on :8080/:8443 an upgrade whose `Origin` is not
  `http(s)://{hostport}` gets 403 (CEL `expression` matcher). On `:8081` there is no check (PWA origin
  differs by design), and a missing `Origin` on `/browser/*` is filled with `http://127.0.0.1:6901`
  because KasmVNC 404s upgrades without it (iroh-fetch in Node sends none).

Evidence (`caddy-test.sh`, `ss`): listeners `127.0.0.1:8080`, `127.0.0.1:8081`, `*:8443` (tcp+udp),
nothing else from Caddy.

| Check | Result |
|---|---|
| `:8080/healthz` | 200 |
| `/` no cookie / bad cookie | 401 / 401 |
| `/` good cookie with client `X-Agentbox-User: attacker`, `X-Iroh-Remote-Id: spoofed`, `X-Agentbox-Proxy-Secret: guess` | upstream sees only `X-Agentbox-User: owner` |
| allow-listed device id sent as `X-Iroh-Remote-Id` on :8080 without cookie | 401 (stripped before forward_auth) |
| `/hermes/api/x` | reaches :8787 as `/api/x`, user `owner`, proxy secret = rendered secret |
| `/browser` → 308, `/browser/` → 302 `?path=browser/websockify`, then 200; unauth 401 | ok |
| WS `/browser/websockify` same-origin / cross-origin / no Origin on :8080 | 101 / 403 / 403 |
| WS on :8443 (HTTP/1.1) same-origin / cross-origin | 101 / 403 |
| `:8443` with `curl --cacert root.crt` by IP | 200, user `owner` |
| headless Chrome through :8080 and :8443 | KasmVNC client connected, Chrome visible (`S6-browser.png`) |
| `:8081` from root / `agentbox` / `agentbox-edge` | refused / refused / 200 (iptables owner rule, see S1) |

**Internal CA fingerprint for the console** (non-interactive, root, after Caddy has provisioned once —
`install-caddy.sh` prints it):

```sh
openssl x509 -in /var/lib/agentbox/caddy/pki/authorities/local/root.crt -noout -fingerprint -sha256 | cut -d= -f2
# e.g. BF:DF:8F:F9:2B:12:BC:8E:F6:AE:03:85:AE:FE:FB:97:48:47:DE:39:20:CE:B4:3C:3F:4D:59:B4:79:16:60:BA
```
The root is valid 10 years, the intermediate rotates; pin/display the **root**. Leaf certs are
short-lived and renewed by Caddy.

## x64

Not executed. During the spike, amd64 emulation in the shared Docker Desktop VM stopped working
for *all* containers (`exec format error`, also the other agent's `abvm-probe`). Cause: installing
`python3` inside the privileged systemd container registers `/usr/lib/binfmt.d/python3.12.conf` and
restarts `systemd-binfmt`, which **flushes every binfmt_misc handler in the (global) Docker VM**,
including Docker Desktop's Rosetta handler. I masked `systemd-binfmt.service` in my containers
afterwards, but the handler has to be restored by Max: restart Docker Desktop, or
`docker run --privileged --rm tonistiigi/binfmt --install amd64` (my attempt to run the latter was
blocked by the permission system). **The `abvm` images should mask `systemd-binfmt.service`.**

What was verified for x64: all amd64 artifacts downloaded on the host and matched the pinned
hashes (KasmVNC deb, Caddy tarball incl. SHA-512, iroh-gateway tarball = release `.sha256`; binaries
are x86-64 ELF); `google-chrome-stable 158.0.8127.36-1` present in `binary-amd64`. The scripts have
no arch-specific logic beyond the asset name. Running Chrome under emulation was not possible to
test (and is irrelevant for the GitHub Actions `ubuntu-24.04` x64 VM path).

## Deviations from the plan

1. `kasmvncserver … -select-de openbox` (§5.3) does not work: openbox isn't a known DE. Pre-seed
   `xstartup` + `.de-was-selected` and drop `-select-de`.
2. KasmVNC needs a `~/.kasmpasswd` write user even with `-DisableBasicAuth`, `command_line.prompt: false`,
   and a readable cert/key even with `require_ssl: false` (own self-signed pair, not `ssl-cert` group).
3. KasmVNC's UDP listener is `0.0.0.0:6901` and can't be disabled → `agentbox-firewall` must drop
   inbound UDP 6901 on non-loopback (v4+v6). §3 "KasmVNC 6901 binds 127.0.0.1 only" is TCP-only.
4. `/browser/` needs `?path=browser/websockify` (Caddy redirect). The 8082 fallback (C9) is not needed.
5. KasmVNC has no WS Origin check and requires an Origin header → Caddy same-origin rule on :8080/:8443,
   Origin fill-in on :8081.
6. arm64 browser = **Google Chrome stable from Google's apt repo** (not Playwright Chromium). Repo file
   is the deb822 `google-chrome.sources` with the new `chrome-stable` URI. CfT zip is the fallback.
7. Chrome unit additions: `--password-store=basic`, `ExecStop` CDP `Browser.close` + `KillMode=mixed`
   (cookie loss otherwise), `ExecStartPre` X-socket wait; KasmVNC unit gets `Upholds=agentbox-chrome.service`.
   `--no-sandbox` not needed (VM AppArmor still to confirm).
8. Caddy admin API must not be TCP :2019 (local privilege escalation) → unix socket; `caddy validate`
   must run as `agentbox-edge`; the release checksum file is SHA-512.
9. Caddyfile path in the spike is `/etc/agentbox/Caddyfile` (plan: `/opt/agentbox/current/Caddyfile`,
   but `agentbox up` renders `@LAN_IP@`, so a rendered copy outside the read-only release dir is needed).
10. `PartOf=agentbox.target` left as a comment; units use `WantedBy=multi-user.target` in the spike.
