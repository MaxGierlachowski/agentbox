## Reload behaviour (answer to "does adding a provider need reload/restart?")

| Change | Plugin | Daemon |
|---|---|---|
| Plugin `add`/`remove` (RPC or CLI) | immediately | immediately (daemon `patchDaemonConfig` writes and applies) |
| `paseo daemon config set --home H agents.providers '<whole object>'` | immediately | immediately (the command reloads a running daemon) |
| Hand edit of `config.json` | immediately (reads the file on every call) | only after `paseo daemon reload --home H` (`appliedPaths: ["agents.providers"]`), **no restart** |

`paseo daemon config set agents.providers.<slug> …` is **rejected** ("Unknown configuration path …
Replace its containing object with JSON for dynamic keys"): set the whole `agents.providers`
object. Do not build it from `paseo daemon config get`: that output redacts keys matching
`password|api_key|access_key|private_key|token|secret|authorization`; read `config.json` directly.
After `paseo plugin install`, `paseo daemon reload` lists `plugins.claude-accounts-usage.*` under
`restartRequiredPaths`; the plugin is already running, no restart is needed.

## Account contract for agentbox

Provider entry (slug rule `^[a-z][a-z0-9-]*$`, not `claude|codex|copilot|opencode|pi|omp|acp`,
`label` required, one dir per account):

```json
"agents": { "providers": { "claude-work": {
  "extends": "claude", "label": "Claude (Work)", "enabled": false,
  "env": { "CLAUDE_CONFIG_DIR": "/home/agentbox/.claude-accounts/claude-work" } } } }
```

Note: the slug must start with a letter. `/home/agentbox/.claude-accounts/<slug>` works with any
valid slug; the plugin's own default is `claude-<name>` in `~/.claude-<name>`, which agentbox
overrides with `--id`/`--config-dir`.

CLI shipped in the tarball (runs as the daemon user; uses `$PASEO_HOME/paseo.pid` +
`local-credential`; JSON on stdout, exit 1 + stderr on error):

```sh
A="node /opt/agentbox/vendor/paseo-multi-account/1.1.0/paseo-multi-account/bin/paseo-claude-accounts.mjs --home /home/agentbox/.paseo"
$A add Work --id claude-work --config-dir /home/agentbox/.claude-accounts/claude-work
$A login start claude-work                      # -> {status:"waiting", url}
printf '%s\n' "$CODE" | $A login code claude-work   # -> succeeded | failed | waiting
CLAUDE_CONFIG_DIR=/home/agentbox/.claude-accounts/claude-work claude auth status   # exit 0, loggedIn true
$A list --usage [--force]
$A switch claude-work                           # {activeId, reloaded, deferred, failed}
$A remove claude-old
```

Login: the plugin spawns `claude auth login` (subscription login is the default = `--claudeai`)
with piped stdio inside the plugin process; URL wait 15 s, code verdict wait 30 s, whole sign-in
times out after 10 min; lost on plugin reload/daemon restart. Not exposed over HTTP; reachable over
the daemon WebSocket as `plugin.rpc.invoke` (`daemon.manage` permission, granted to the local
credential), which the CLI wraps. agentbox may instead run `claude auth login` in its own PTY with
the same `CLAUDE_CONFIG_DIR`; the plugin reads whatever lands there. `claude auth status` reports
`loggedIn: true` for any present credentials file (it does not validate the token).

Per-agent pinning: not supported. The plugin forces `CLAUDE_CONFIG_DIR` of the active account onto
every session of `claude` and of providers extending it, including
`paseo agent run --env CLAUDE_CONFIG_DIR=…`; creating an agent on a disabled account provider fails
("Provider 'claude-delta' is disabled"). paseo-mcp's `defaultAccount` therefore cannot pin a chat
to an account; all Claude chats follow the global switch.

## Exact commands

```sh
# Mac (repo)
git checkout v1 && npm ci && npm run typecheck && npm test
npm run release:tarball      # dist/paseo-multi-account-1.1.0.tgz + .sha256

# image
docker build -t ab-pma-node24:0.17.3 - <<'EOF'
FROM node:24.22.3-bookworm
RUN npm install -g @getpaseo/cli@0.17.3 @anthropic-ai/claude-code@2.1.330 --no-audit --no-fund
RUN useradd -m -u 10001 agentbox
USER agentbox
WORKDIR /home/agentbox
EOF

# full scripted check, offline and online (both PASS)
docker run --rm --name ab-pma-smoke --network none \
  -v $PWD/dist:/dist:ro -v $PWD/scripts:/scripts:ro ab-pma-node24:0.17.3 \
  bash /scripts/smoke-linux.sh /dist/paseo-multi-account-1.1.0.tgz
docker run --rm --name ab-pma-smoke-net \
  -v $PWD/dist:/dist:ro -v $PWD/scripts:/scripts:ro ab-pma-node24:0.17.3 \
  bash /scripts/smoke-linux.sh /dist/paseo-multi-account-1.1.0.tgz
```

`scripts/smoke-linux.sh` (in the repo, also run by CI) does, with `H=$PASEO_HOME`:

```sh
paseo daemon config set --home $H daemon.listen 127.0.0.1:6767
paseo daemon config set --home $H daemon.relay.enabled false
paseo daemon config set --home $H features.webUi.enabled false
paseo daemon config set --home $H pluginsEnabled true
paseo daemon config set --home $H agents.providers '{"claude-alpha":{…},"claude-beta":{…}}'
paseo daemon run --home $H &                     # then poll /api/health
sha256sum -c paseo-multi-account-1.1.0.tgz.sha256 && tar xzf paseo-multi-account-1.1.0.tgz -C <vendor>
paseo plugin install <vendor>/paseo-multi-account --home $H
paseo plugin ls claude-accounts-usage --home $H --json      # status running
<cli> list | switch claude-beta | list --usage --force | add Gamma --id claude-gamma --config-dir … \
      | remove claude-beta (refused) | remove claude-gamma
<hand edit config.json> ; <cli> list (sees it) ; paseo provider ls (doesn't) ;
paseo daemon reload --home $H --json ; paseo provider ls (does)
paseo agent run --home $H --no-wait --provider claude --cwd <dir> "reply ok"   # check /proc/<pid>/environ
```

Manual extras in a long-running container: switch with live busy chats (`paseo agent run` ×2,
`switch`, `paseo agent stop`, `paseo agent send`), `login start|status|cancel`, `plugin remove` +
`install <newdir>`, `paseo daemon stop` + `run`.

## Notes and open issues

- Per-agent pinning is missing (design question for Max: e.g. let chats on a per-account provider
  keep their own dir, which would also need Paseo to allow agents on disabled providers, or a pin
  map in `claude-accounts.json` keyed by agent ID or label).
- The tarball sha256 is not reproducible across builds (tar mtimes); agentbox must take the
  `.sha256` that comes with the attached asset.
- The daemon tries to download a local speech model from github.com at startup (fails harmlessly
  offline). Not plugin related; agentbox may want to turn dictation off.
- `private: true` stays in package.json: the tarball flow does not need npm publishing.
- Final tarball built on the Mac: `paseo-multi-account-1.1.0.tgz`, sha256
  `2ee414766f9ffd032b56cc2dd4761ac4393e244e782da77026e02e1410eb96ff`, 3.46 MB; CI builds its own
  (artifact `paseo-multi-account-tarball`).
