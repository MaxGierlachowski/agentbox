# S1 — iroh-gateway 0.6.4 behind Caddy (2026-11-22)

Setup: `abvm:arm64` container (Ubuntu 24.04 + systemd) with `agentbox-iroh.service` (iroh-gateway
as `agentbox-edge`) → Caddy `127.0.0.1:8081` → stand-in backends (`dummy-backend.py` as the agentbox
config server on :7777 incl. `/api/auth/check`, and as hermes-ui on :8787) and the real KasmVNC on
:6901. Client: the Mac host (Node 24.20.0), `iroh-fetch@0.6.4` in a temp dir, `iroh-probe.mjs`
with a fixed `secretKey` from a 0600 key file (never printed). Docker Desktop NAT; n0 public relays.

Result: **pass.** HTTP, cookies, SSE, WebSocket upgrade, `X-Iroh-Remote-Id`, allow lists, SIGHUP
reload, live revoke, stable endpoint id, admin endpoints all work as desk-verified.

## Unit (`agentbox-iroh.service`)

`User=agentbox-edge`, `Environment=IROH_KEY_FILE=/var/lib/agentbox/iroh/gateway.key
IROH_CONFIG_FILE=/var/lib/agentbox/iroh/gateway.env IROH_ADMIN_ADDR=127.0.0.1:8090
RUST_LOG=iroh_gateway=info`, `ExecReload=/bin/kill -HUP $MAINPID`, `Restart=always`, plus the
upstream sandboxing set (`ProtectSystem=strict`, `ReadWritePaths=/var/lib/agentbox/iroh`,
`SystemCallFilter=@system-service`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK`, …).
`BACKEND_URL` lives in `gateway.env` (its values override env/flags and are re-read on HUP).

Initial `gateway.env` (no devices, no pairing window):
```
BACKEND_URL=http://127.0.0.1:8081
IROH_ALLOW_CLIENTS=
IROH_ALLOW_PATHS=/__closed__
```

`:8081` uid firewall (in the container, `iptables` 1.8 nft backend):
```
iptables  -A OUTPUT -o lo -p tcp --dport 8081 -m owner ! --uid-owner agentbox-edge -j REJECT
ip6tables -A OUTPUT -o lo -p tcp --dport 8081 -m owner ! --uid-owner agentbox-edge -j REJECT
```
root → 127.0.0.1:8081 refused, `agentbox` → refused (also `[::1]:8081`), `agentbox-edge` → 200,
`agentbox` → :8080 → 200. Caddy also binds :8081 on 127.0.0.1 only, so IPv6 is closed twice.
The rule stores the numeric uid (999 here); `agentbox-firewall.service` must re-apply it at boot
(`-C` before `-A` keeps it idempotent, as in the script).

## Findings / deviations

1. **Reload errors are silent to systemd.** A bad `gateway.env` keeps the old config and only logs a
   WARN. `agentbox host apply iroh-config` must validate ids itself (64 hex, valid ed25519 point) before
   rendering and then confirm the result (journal "configuration reloaded" after the HUP, or compare
   behaviour), otherwise a revoke can silently not happen. `/status` does not show the allow list.
2. KasmVNC refuses websocket upgrades without `Origin` (404); iroh-fetch in Node sends none →
   Caddy :8081 fills `Origin` for `/browser/*` (S6 Caddyfile). Check in S7 what the PWA shim sends.
3. **CSRF/CSWSH through `agentbox connect`:** on :8081 identity is the device id, not a cookie. The
   laptop proxy (`agentbox connect` on `localhost:8080`) therefore authenticates *every* local caller,
   including any website open in the laptop's browser (fetch/WS to `http://localhost:8080`, DNS
   rebinding). WP-AB-6 must make the local proxy check `Host` ∈ {localhost:<port>, 127.0.0.1:<port>}
   and reject cross-origin `Origin` on state-changing requests and WS upgrades (or keep the session
   cookie requirement on top of the device id for browser traffic).
4. The probe's `secretKey` approach confirms C1/S8 direction: `createIrohFetch({secretKey, engine:"native"})`
   is all `agentbox connect` needs; the native addon gives direct paths. Browser WASM test page (PWA)
   was not part of this run (S7).
5. `/healthz` 503-when-offline was not re-tested (relay was always reachable here).
