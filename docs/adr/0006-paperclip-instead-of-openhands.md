# 0006 – Paperclip instead of OpenHands

- Status: superseded by 0007, then by 0008 (supersedes 0005)
- Date: 2026-10-05

## Context

OpenHands was evaluated and is not good enough for our use. Paperclip (paperclip.ing,
github.com/paperclipai/paperclip) orchestrates teams of coding agents behind a web UI with
email/password login. Its login should be reachable on a public URL.

## Decision

- Paperclip runs as a Compose service (`paperclip` + `paperclip-db` on postgres:17), image built
  from the pinned Paperclip digest plus our toolchain, browser and agent layers. Agents started by
  Paperclip (`claude_local`, `codex_local`, …) run in that container.
- Mode `authenticated` + exposure `public`. Secrets are generated by agentbox and kept in the age
  store.
- The root user, company and settings are entered in the agentbox UI first. agentbox bootstraps
  the instance (sign-up, `paperclipai auth bootstrap-ceo`, accept invite), creates the company,
  then restarts with sign-up disabled.
- Only after `bootstrapStatus = ready` does agentbox enable `tailscale funnel` on 443. The agentbox
  UI moves to tailnet-only `serve` on 8443 and rejects requests carrying `Tailscale-Funnel-Request`.

## Consequences

- One deliberately public surface. An un-bootstrapped Paperclip is never public, because the
  first person to sign up there could become admin, and admin means running agents on the VM.
- Paperclip had several critical advisories in 2026: pin by digest, apply security releases
  immediately, keep a funnel kill switch in the UI, never mount the Docker socket.
- No VM port is opened for the public URL. A custom domain would need Caddy and open ports 80/443
  later.
